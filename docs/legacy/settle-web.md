# تسویه فروش (settle-web)

صورتحساب سقف حجم (`data_limit`) برای ادمین/فروشندهٔ PasarGuard. مصرف `used_traffic` در مبلغ نمی‌آید.

هویت کاربر **id پنل** است. شارژ مجدد همان نام قدیمی را صفحه به‌صورت «شارژ مجدد» نشان می‌دهد.

## صفحه

`https://${PANEL_DOMAIN}:2096/settle/`

سرویس Exit: `settle-web` روی `127.0.0.1:8789`.

## دو نوع ورود

| ورود | دسترسی |
|------|--------|
| حساب مدیر `settle` (رمز: `/etc/settle-web/admin.pass`) | همهٔ ادمین‌ها، قیمت، تسویه، هزینه/سود، تأیید بخشش، انتساب زیرمجموعه |
| نام کاربری و رمز **پنل PasarGuard** هر ادمین | حساب خودش، گزارش، درخواست حذف بدون هزینه، فروش ماهانهٔ خودش |
| همان ورود، اگر **مدیر ارشد** باشد (مدیر زیر نظر دارد) | لیست مدیران + فروش/بدهی هرکدام + حساب خودش |

## نمایندگی (مدیر ارشد / مدیر)

یک سطح: مدیر ارشد ← چند مدیر.

1. در PasarGuard چند ادمین با نقش محدود بسازید.
2. با حساب مدیر `settle` در لیست ادمین‌ها، برای هر مدیر از منوی **مدیر ارشد** والد را انتخاب و ذخیره کنید.
3. طرف‌حساب شما فقط **مدیر ارشد** است؛ مدیران با او تسویه می‌کنند.
4. روی صفحهٔ مدیر ارشد، بلوک **شبکه نمایندگی** فروش هر مدیر را جدا نشان می‌دهد.
5. **ثبت تسویه شبکه** (یا واریز کارت‌به‌کارت با کد مدیر ارشد) دفترچهٔ خودش + همهٔ مدیران را می‌بندد؛ ماندهٔ بدهی فقط روی مدیر ارشد می‌ماند. حجم زیرمجموعه‌ها برای تسویه با مالک با **قیمت عمدهٔ مدیر ارشد** حساب می‌شود (نه قیمت خرده‌ای که به مدیرانش داده)؛ حاشیه برای مدیر ارشد می‌ماند.
6. مدیر ارشد می‌تواند **قیمت تومان/گیگ** هر مدیر زیر نظرش را خودش در صفحهٔ همان مدیر تنظیم کند (مثلاً ۴۰۰۰)؛ آن قیمت فقط دفتر داخلی ارشد↔مدیر است.

## ضد سوءاستفادهٔ حذف

هر ~۹۰ ثانیه سقف کاربران اسکن می‌شود. اگر یوزر از پنل حذف شود ولی سقفش از «قبلاً حساب‌شده» بیشتر باشد، در جدول با وضعیت **deleted** می‌ماند و در بدهی می‌آید.

## حذف بدون هزینه (انصراف مشتری)

1. روی ردیف کاربر → **حذف بدون هزینه** + دلیل
2. مدیر در منوی **حذف بدون هزینه** تأیید یا رد می‌کند (مهلت ۴۸ ساعت؛ نوتیف تلگرام)
3. فقط بعد از **تأیید** بدهی آن `id` بخشیده می‌شود؛ بعد می‌توان از پاسارگارد حذف کرد
4. حذف بدون تأیید → بدهی می‌ماند

## فروش ماهانه / هزینه و سود

- **فروش ماهانه:** مجموع تسویه‌های `charge` هر ماه + بخشش‌ها؛ برای ادمین فقط خودش
- **هزینه و سود** (فقط مدیر): هزینهٔ ماه را وارد کنید؛ سود = فروش − هزینه

## گزارش برای فروشنده

- **کپی / دانلود گزارش فروش** — فقط جدید + شارژ مجدد + حذف‌شدهٔ بدهکار
- تیک **فقط جدید و شارژ مجدد**

## اولین بار

اگر تا الان دستی تسویه کرده‌اید: **بدون دریافت ثبت کن**. از آن به بعد فقط افزایش سقف حساب می‌شود.

## تسویه جزئی و بدهی

در **دریافتی** مبلغ واقعی را بزنید و ثبت تسویه کنید؛ مانده بدهی می‌ماند.

## تنظیمات (برند /pay/ + پیامک بانک)

صفحهٔ **تنظیمات** (فقط مدیر / ادمین ۱):

- **برند /pay/:** نوار بالای دکور، شعار ورود، عنوان/متن خوش‌آمد بعد از ورود، تلفن و تلگرام عمومی
- بعد از ورود مشتری نوار دکور مخفی می‌شود و متن خوش‌آمد بالای پلن‌ها می‌آید
- **پیامک بانک:** فرستنده، توکن وب‌هوک، … — خبر تلگرام با `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` در `/root/.vpn-secrets/.env`

## خرید سلف‌سرویس مشتری (`/pay/`)

`https://panel…/pay/` — بدون لاگین settle.

1. در settle منوی **فروش به مشتری**: شماره کارت + پلن (گیگ / روز / تعداد کاربر / قیمت) برای هر ادمین؛ در `/pay/` به‌صورت «N کاربره» دیده می‌شود
2. شخصی‌سازی فروشنده: نام کسب‌وکار، **شعار من**، کانال تلگرام، شماره و شناسه پشتیبانی (تماس؛ برند عمومی از **تنظیمات**)
3. پلن نامحدود (گیگ `0`) **فقط برای ادمین `#1`**؛ برای بقیه در UI مخفی و در API رد می‌شود
4. صفحه `/pay/` ظاهر لندینگ لوازم‌جانبی دارد؛ ورود با نام‌کاربری(+رمز نمایشی) و بعد بسته‌ها + خوش‌آمد
5. همان وب‌هوک پیامک اگر مبلغ با سفارش `pending` یکی باشد، سقف/انقضا را اعمال می‌کند
6. افزایش سقف بعداً در بدهی settle همان ادمین دیده می‌شود

فونت: `IRANYekanX-Medium.woff2` → `scripts/settle-web/static/` سپس `install.sh`

نیاز: `PANEL_API_KEY` در `/root/.vpn-secrets/.env`.

## نصب

```bash
sudo AUTH_USER=settle AUTH_PASS='...' /root/vpn-infra/scripts/settle-web/install.sh
```
