NODE-DISABLED.md

چرا نود ایران در پنل PasarGuard خاموش است؟

آنچه پنل «طبیعی» می‌خواهد

PasarGuard یک ردیف Node دارد. اگر آن را Enable کنید:

  1. پنل از آلمان به API نود ایران وصل می‌شود: https://<IP-ایران>:62050/start
  2. کل کانفیگ Xray + همهٔ کاربران را در body می‌فرستد
  3. نود ایران پروسس xray -c stdin: را با آن JSON بالا می‌آورد

تا وقتی این مسیر سالم باشد، پنل خودش کاربر جدید را روی ایران اعمال می‌کند و آمار را می‌گیرد. اسکریپت iran-sync-* لازم نیست.

چرا در این استک Enable نشد (و خطرناک است)

سه واقعیت با هم جمع شدند:

  1. هستهٔ زنده ایران docker است (pasarguard/node). JSON روی دیسک /root/.pg_nodes/iran/xray.json را systemd اجرا نمی‌کند. تا /start نخورد، Reality روی :443 کانفیگ پنل را ندارد.
  1. آلمان → ایران :62050: نود جواب HTTP 200 می‌دهد ولی body بزرگ است (کل هسته + کاربران). کلاینت HTTP پنل روی خواندن body timeout می‌شود، retry می‌کند، و پنل وضعیت LockControl می‌گیرد. نود از نظر UI «خراب» می‌شود در حالی که Xray ممکن است نیمه‌کاره بالا آمده باشد.
  1. ایران → آلمان پنل روی IP خام / :2096: DPI بعد از TLS، HTTP را می‌خورد. نود ایران نباید برای سینک به panel:2096 عمومی poll کند.

نتیجهٔ عملی: Enable کردن نود در UI مسیر رسمی را دوباره باز می‌کند و همان timeout/LockControl برمی‌گردد. ردیف نود را پاک نکنید (تگ اینباند کاربران به همان نود وصل است) — فقط disabled / keep_alive=0 بماند.

جایگزین که الان کار می‌کند:

  • آلمان هر ۱۰ث از sqlite پنل protobuf می‌سازد → SCP به ایران
  • ایران اگر hash عوض شده (یا :443/:2053 خواب است) locally POST https://127.0.0.1:62050/start
  • آمار را iran-stats با SSH و xray api statsquery به sqlite پنل می‌نویسد — چون نود disabled است پنل خودش usage را نمی‌پرسد

روی سرور دوست می‌شود «درست» کرد؟

شاید، بعد از اینکه استک با سینک SCP بالا آمد — نه در روز اول.

تست اجباری از Exit جدید، قبل از هر Enable:


# از آلمان: آیا POST به نود ایران تمام body را بدون timeout برمی‌گرداند؟
# اگر curl به 62050 در کمتر از مثلاً 20s تمام شود و پنل timeout کوتاه‌تری دارد، باز هم ممکن است Fail شود.
curl -vk --max-time 60 -o /tmp/node-start.out -w 'http:%{http_code} time:%{time_total}\n' \
  --resolve node.example:62050:IRAN_IP \
  https://node.example:62050/health   # یا هر endpoint سلامت نود

اگر هر دو برقرار بود:

  • آلمان می‌تواند TCP+TLS+HTTP کامل به :62050 ایران بزند (فایروال فقط IP Exit)
  • پنل PasarGuard شما timeout بالاتر از زمان واقعی /start دارد (باید با نسخهٔ پنل چک شود)

آن‌وقت می‌توان معماری رسمی را امتحان کرد: Enable نود، iran-sync-export/apply را متوقف کرد، و دید LockControl نمی‌آید.

اگر تست fail شد (احتمال زیاد وقتی یک سرور ایران و یکی خارج است): همان طرح فعلی را نگه دارید. این باگ محصول نیست؛ محدودیت شبکه + timeout کلاینت پنل است. «اصلاح» واقعی یا طولانی‌کردن timeout پنل است یا همین صف SCP.

قانون پرامپت Cursor دوست: تا وقتی تست /start از Exit موفق و تکرارپذیر نشده، نود را Enable نکن. ردیف را بساز و disabled بگذار.

IMPLEMENTATION-GUIDE.md

راهنمای پیاده‌سازی استک VPN دوهاب — ۹ مرحله

نسخه: ۲۴ اوت ۲۰۲۶. این سند برای شما است تا روی سیستم شخصی نگه دارید. سکرت نمی‌خواهد. IP/دامنهٔ استک فعلی فقط مثال است؛ روی سرور دوست همه را عوض کنید.

استک فعلی (مثال، کپی نکنید): رله ایران ${IRAN_IP} · Exit آلمان ${EXIT_IP} · دامنه‌ها ${MAIN_ZONE} / ${ALT_ZONE}.

دو ماشین لازم است. کلاینت به ایران وصل می‌شود؛ اینترنت از آلمان خارج می‌شود. پنل PasarGuard روی Exit است.

قبل از شروع فایل NODE-DISABLED.md را بخوانید.

مرحله ۱ — دامنه، Cloudflare، گواهی

هدف: نام‌ها resolve شوند و یک گواهی TLS با SAN درست برای پنل، ورود Vision، و بک‌هال XHTTP وجود داشته باشد.

کارها

  1. دو دامنه (یا یکی با چند subdomain). از ایران .ir معمولاً بهتر از دامنه‌ای است که DNS-hijack می‌شود.
  2. هر دو را روی Cloudflare بگذارید. توکن API با حداقل دسترسی Zone DNS (نه account-wide اگر می‌شود).
  3. تنظیم زون: SSL Full (Strict)، HTTP/3 خاموش (وگرنه بعضی اندروید ERR_QUIC_PROTOCOL_ERROR).
  4. رکوردها (نمونه نام؛ IP را مال خودتان بگذارید):

- ir.<دامنه> → IP ایران، خاکستری (ورود Reality/Vision). هرگز نارنجی نکنید.

- panel.<دامنه-ایران> → IP ایران، خاکستری اگر پنل را روی پورت ۲۰۹۶ از ایران می‌خواهید. نارنجی پورت ۲۰۹۶ را رد نمی‌کند.

- panel.<دامنه-آلمان> → IP آلمان، نارنجی برای پنل روی ۴۴۳.

- cdn.<دامنه> و xhttp.<دامنه> → IP آلمان، نارنجی — بک‌هال، ورود کلاینت نیست.

  1. گواهی Let’s Encrypt با DNS challenge (Cloudflare)، یک cert با SAN همهٔ panel. / ir. / cdn. / xhttp.. روی آلمان صادر شود؛ fullchain+privkey به ایران کپی شود (مثلاً /root/.pg_nodes/certs/ و /etc/nginx/certs/).

چک

  • dig +short ir.دامنه = IP ایران
  • openssl s_client -connect ir.دامنه:2053 -servername ir.دامنه بعد از مرحله ۴ باید verify شود
  • سکرت توکن CF فقط در /root/.vpn-secrets/.env با mode 600

مرحله ۲ — Exit: فایروال، Xray بک‌هال، nginx

هدف: آلمان XHTTP و DIRECT را گوش بدهد؛ پنل روی ۲۰۹۶ و SNI روی ۴۴۳ جدا شود.

نصب

  • Ubuntu 22.04، nftables، SSH فقط کلید
  • Xray + geoip.dat / geosite.dat
  • nginx با ماژول stream (ssl_preread)

کارها

  1. nftables شبیه configs/nftables-exit.conf:

باز از جهان: 22, 80, 443, 2096

فقط از IP ایران: 9443 TCP و UDP بک‌هال اگر استفاده می‌کنید

127.0.0.1:8000 پنل از بیرون دیده نشود.

  1. Xray Exit (جدا از JSON پنل):

- XHTTP روی 127.0.0.1:10443 (نه :443 عمومی) path مثلاً ${XHTTP_PATH}

- DIRECT/Vision+TLS روی :9443 فقط برای ایران

- outbound PANEL-LOCAL = redirect به 127.0.0.1:2096 برای دامنهٔ panel.*

- اختیاری WARP برای گوگل

  1. nginx stream روی :443: SNI panel.* → 127.0.0.1:2096؛ پیش‌فرض → 127.0.0.1:10443
  2. nginx http روی :2096 TLS → http://127.0.0.1:8000 (بعد از مرحله ۳)

چک

  • ss -tlnp : nginx :443 و :2096؛ xray :10443 لوپ‌بک و :9443
  • از ایران، TCP به :9443 آلمان باز باشد؛ از IP غریبه بسته

مرحله ۳ — پنل PasarGuard روی Exit

هدف: UI و sqlite و API روی آلمان؛ هستهٔ iran-xray منبع حقیقت بک‌هال و اینباند کلاینت باشد.

نصب

  • Docker
  • تصویر PasarGuard؛ بایند 127.0.0.1:8000 (نه 0.0.0.0)
  • دیتابیس پایدار مثلاً /var/lib/pasarguard/

کارها

  1. پنل را بالا بیاورید؛ ادمین بسازید.
  2. یک Core بسازید (iran-xray) شامل:

- inbound VLESS-REALITY پورت ۴۴۳

- inbound VLESS-VISION پورت ۲۰۵۳

- inbound PANEL-ADMIN SOCKS فقط 127.0.0.1:11080 (از assignment کاربر خارج)

- outboundهای TO-AMS-CF / TO-AMS-XHTTP / TO-AMS-DIRECT (+ TUIC اگر خواستید)

- balancer backhaul با selector اولویت CF → XHTTP → DIRECT

- قبل از catch-all .ir DIRECT: دامنهٔ panel.* برود backhaul نه DIRECT

  1. کلاینت داخل JSON هسته خالی باشد؛ کاربر از UI اضافه می‌شود.
  2. یک ردیف Node برای ایران بسازید (آدرس، پورت API 62050، گواهی نود) ولی Enable نکنید. keep_alive=0.
  3. Hostهای ساب: Reality با آدرس ir. و/یا IP ایران پورت ۴۴۳؛ Vision پورت ۲۰۵۳ با SNI ir..

چک

  • https://panel.دامنه-آلمان:2096/dashboard/ از شبکهٔ غیر ایران یا از روی VPN باز شود
  • نود در UI وضعیت disabled
  • فایل API key پنل فقط mode 600 روی دیسک؛ در چت نگذارید

مرحله ۴ — رله ایران: node، Reality، Vision

هدف: کلاینت به ایران وصل شود. Xray زنده از docker node است نه از unit قدیمی systemd.

نصب

  • nftables (configs/nftables-iran.conf): TCP 22, 443, 2053, 8443, 2096؛ UDP 443؛ API نود 62050/62051 فقط از IP Exit
  • Docker تصویر pasarguard/node، volume مثلاً /var/lib/pg-node
  • گواهی SAN برای Vision و بعداً nginx پنل

کارها

  1. نود را با گواهی و API key مطابق ردیف پنل اجرا کنید؛ منتظر /start محلی بمانید (مرحله ۵).
  2. Reality روی *:443 (مال nginx نباشد).
  3. Vision روی *:2053.
  4. اسکریپت bootstrap-iran.sh را چشم‌بسته اجرا نکنید؛ فرضش Xray systemd است و با معماری زنده فرق دارد.

چک

  • بعد از اولین apply: ss نشان دهد xray روی :443 و :2053
  • از موبایل ایران یک لینک Reality با fragment (tlshello) وصل شود
  • openssl s_client به :2053 با SNI ir.دامنه گواهی شما را نشان دهد

مرحله ۵ — صفحه کنترل: سینک SCP + apply محلی

هدف: ساخت/حذف کاربر در پنل ظرف ~۲۰ث روی ایران اعمال شود بدون Enable نود.

کپی از بستهٔ اسکریپت (بازنویسی نکنید)

  • Exit: iran_sync_export.py, build_iran_start_proto.py, iran_stats_ingest.py + unitهای iran-sync-export و iran-stats
  • ایران: iran_sync_apply.py → /usr/local/sbin/iran_sync_apply.py + unit iran-sync-apply

کارها

  1. SSH کلید از root آلمان به root ایران بدون پسورد (BatchMode=yes).
  2. در اسکریپت‌ها IRAN=root@<IP-ایران> را عوض کنید.
  3. Export هر ۱۰ث proto را در /var/lib/pasarguard/iran-sync/ می‌سازد؛ اگر hash عوض شد SCP به /var/lib/pg-node/sync/
  4. Apply هر ۱۰ث اگر hash جدید است (یا پورت ۴۴۳/۲۰۵۳ خواب است) POST https://127.0.0.1:62050/start
  5. Stats هر ۳۰ث از ایران statsquery می‌گیرد و used_traffic / online_at را در sqlite می‌نویسد
  6. Instant Instagram inject داخل export است؛ لیست کاربر را از /etc/vpn-monitor/ می‌خواند نه از git

چک

  • یک کاربر تست در پنل → ظرف ۲۰ث در /var/lib/pg-node/generated/xray.json ایران email/id او باشد
  • لاگ: Exit /var/log/vpn-path/ (اگر اسکریپت همان path را دارد) · ایران sync.log
  • نود همچنان disabled
  • systemctl list-timers هر سه تایمر active

مرحله ۶ — بک‌هال: CF، XHTTP، DIRECT

هدف: ترافیک کاربر از ایران به آلمان برسد. vpn-path روی آلمان selector را در هستهٔ پنل عوض می‌کند؛ بعد export همان را به ایران می‌رساند.

کپی: کل خانوادهٔ vpn-path + vpn_failover.py + path_health.py + timer failover. IP/دامنه را عوض کنید.

کارها

  1. اولویت پیشنهادی: TO-AMS-CF → TO-AMS-XHTTP → TO-AMS-DIRECT (TUIC آخر؛ UDP اغلب از دیتاسنتر ایران فیلتر است)
  2. نصب: install -m 755 scripts/vpn-path /usr/local/sbin/vpn-path
  3. روی ایران stub بگذارید که بگوید vpn-path را روی Exit بزن (یا status از generated بخواند)
  4. vpn-failover.timer هر ۱۵ث از ایران health بگیرد؛ ۳ شکست پیاپی → مسیر بعدی
  5. Fragment روی outboundهای TLS بک‌هال (dialerProxy) طبق JSON هسته

چک از ایران


curl -sS --max-time 20 -x socks5h://127.0.0.1:11080 -o /dev/null -w '%{http_code}\n' https://www.google.com/generate_204

روی Exit: vpn-path status و vpn-path test

اگر CF فیلتر شد: vpn-path xhttp یا direct.

مرحله ۷ — پروکسی پنل روی ایران (لینک ساب بدون تغییر)

هدف: کلاینت‌های ایران همان URL ذخیره‌شده https://panel.<دامنه>:2096/sub/<token> را باز کنند؛ DNS به IP ایران باشد.

کپی: configs/nginx-iran-subproxy.conf + snippets، xray-subproxy.json، xray-subproxy.service، nft پورت ۲۰۹۶.

کارها

  1. nginx ایران listen 2096 و 8443 با همان گواهی SAN
  2. proxy_pass به https://127.0.0.1:10444 (dokodemo)
  3. dokodemo مقصدش دامنه‌ای باشد که بعد از عوض شدن DNS پنل ایران حلقه نزند — در استک فعلی ${PANEL_DOMAIN}:2096 (آن یکی روی آلمان ماند)
  4. Host هدر همان hostname لینک کلاینت
  5. location / کل پنل را پروکسی کنید (نه فقط /dashboard/) چون اسکریپت‌ها زیر /statics/اند
  6. DNS panel.<دامنه-ایران> خاکستری به IP ایران

چک از خود ایران


curl -sS -o /dev/null -w '%{http_code}\n' --resolve panel.دامنه:2096:127.0.0.1 https://panel.دامنه:2096/dashboard/
# باید 200 و HTML شامل /statics/ باشد

از آلمان به IP ایران :2096 ممکن است HTTP بعد از TLS hang شود؛ کلاینت هدف نت ایران است.

SCRIPTS-INSTALL.md

اسکریپت‌ها: چیست، کجا نصب می‌شود، چطور

بسته: vpn-infra-portable-scripts.tar.gz — بدون __pycache__، بدون لیست کاربر اینستا، بدون .env سکرت.

قبل از نصب روی سرور جدید این رشته‌ها را در فایل‌ها عوض کنید:

  • ${IRAN_IP} → IP رله ایران جدید
  • ${EXIT_IP} → IP Exit جدید
  • root@${IRAN_IP} → root@<ایران>
  • دامنه‌های ${MAIN_ZONE} / ${ALT_ZONE} / ${EXTRA_ZONE} → دامنهٔ دوست
  • مسیر /root/vpn-infra اگر ریپو جای دیگری است

CURSOR-PROMPT.md

پرامپت Cursor برای پیاده‌سازی استک VPN دوهاب

این متن را کامل در چت Cursor روی سرورهای جدید پیست کنید. پوشهٔ vpn-infra-portable-scripts.tar.gz و این داکیومنت‌ها را هم به workspace بدهید (extract کنید به /root/vpn-infra یا مسیر واحد دیگر).

از استک قبلی هیچ سکرتی کپی نکنید: UUID، کلید Reality، توکن Cloudflare، API پنل، پسورد، sqlite، لیست کاربر اینستاگرام.

شما یک مهندس زیرساخت هستید. باید همین معماری را روی دو سرور خالی پیاده کنید، نه یک VPN تک‌سروره و نه بازنویسی اسکریپت‌های آماده.

معماری اجباری (عوض نکنید مگر تست شبکه خلافش را ثابت کند)

دو هاپ:


کلاینت در ایران
  → رله ایران: VLESS Reality TCP 443 + VLESS Vision TCP 2053
  → بک‌هال به Exit: اولویت TO-AMS-CF (XHTTP پشت Cloudflare) سپس TO-AMS-XHTTP سپس TO-AMS-DIRECT (VLESS+TLS روی پورت 9443 فقط از IP ایران)
  → Exit خارج: خروج اینترنت (اختیاری WARP برای گوگل)

کلاینت به Exit وصل نمی‌شود. Reality روی ایران :443 است؛ آن پورت را nginx نکنید.

پنل PasarGuard فقط روی Exit، bind به 127.0.0.1:8000. nginx Exit TLS روی :2096. روی Exit پورت 443 عمومی nginx stream ssl_preread است: SNI دامنهٔ پنل → 127.0.0.1:2096؛ بقیه → XHTTP روی 127.0.0.1:10443 (Xray Exit روی 443 عمومی listen نکند).

هستهٔ JSON پنل (core ایران) از هستهٔ Xray Exit جدا است. پنل را به JSON بک‌هال Exit وصل نکنید.

نود پنل — قانون سخت

یک ردیف Node برای ایران در پنل بسازید (API معمولاً :62050) ولی Enable نکنید؛ keep_alive=0.

علت: POST آلمان→ایران /start در عمل 200 می‌دهد ولی body بزرگ timeout می‌شود و پنل LockControl می‌گیرد. Xray زنده ایران فقط وقتی کانفیگ می‌گیرد که خود ایران POST https://127.0.0.1:62050/start بزند.

جایگزین اجباری در روز اول:

  • Exit هر ~۱۰ث: iran_sync_export.py از sqlite protobuf می‌سازد، اگر hash عوض شد SCP به ایران /var/lib/pg-node/sync/
  • ایران هر ~۱۰ث: iran_sync_apply.py اگر hash جدید است یا :443/:2053 خواب است، localhost /start
  • Exit هر ~۳۰ث: iran_stats_ingest.py با SSH xray api statsquery روی ایران و نوشتن used_traffic در sqlite

ردیف Node را حذف نکنید. تا وقتی از Exit، POST کامل به :62050 ایران بدون timeout تکرارپذیر نشده، Enable نکنید. جزئیات در docs/friend-deploy/NODE-DISABLED.md.

ایران هرگز برای سینک نود به https://panel:2096 روی IP عمومی Exit وصل نشود (DPI بعد از TLS). دسترسی انسان به پنل از ایران از مسیر بک‌هال / پروکسی محلی است.

دامنه و Cloudflare

از اپراتور بپرسید: دو IP (ایران و Exit)، نام دامنه‌ها، توکن CF.

زون: SSL Full Strict، HTTP/3 خاموش.

  • ir.<دامنه> A به IP ایران، DNS only (خاکستری). ورود VPN. نارنجی ممنوع.
  • panel.<دامنه> اگر پورت 2096 از ایران می‌خواهید: A به IP ایران، خاکستری.
  • یک panel.* برای Exit می‌تواند نارنجی باشد (فقط 80/443).
  • cdn. / xhttp. نارنجی به IP Exit — بک‌هال نه ورود کلاینت.

گواهی Let’s Encrypt یک cert با SAN همهٔ این نام‌ها. گواهی جدید الکی نگیرید اگر SAN کافی است.

از ایران بعضی دامنه‌ها DNS-hijack می‌شوند؛ با dig @8.8.8.8 از رله چک کنید.

بک‌هال و پنل از ایران

در routing ایران، قبل از قانون DIRECT برای geosite:category-ir / .ir، دامنهٔ panel. باید برود balancer backhaul. روی Exit همان نام‌ها outbound PANEL-LOCAL → 127.0.0.1:2096.

SOCKS ادمین روی ایران: 127.0.0.1:11080 inbound PANEL-ADMIN، localhost-only، جزء کاربران پنل نباشد.

پروکسی شفاف پنل روی ایران: nginx :2096 + :8443، upstream 127.0.0.1:10444 (xray-subproxy → SOCKS → بک‌هال). مقصد dokodemo باید دامنه‌ای باشد که DNS-اش روی خود ایران حلقه نزند. کل location / را پروکسی کنید (/statics/، /api/، /sub/) وگرنه داشبورد سفید است. proxy_ssl_verify off روی لوپ‌بک. nft TCP 2096 باز.

فایروال (حداقل)

ایران: TCP 22, 443, 2053, 8443, 2096؛ UDP 443؛ 62050/62051 فقط از IP Exit.

Exit: TCP 22, 80, 443, 2096 از جهان؛ 9443 و UDP بک‌هال فقط از IP ایران؛ پنل 8000 از بیرون بسته.
