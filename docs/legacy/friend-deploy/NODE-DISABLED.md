# چرا نود ایران در پنل PasarGuard خاموش است؟

## آنچه پنل «طبیعی» می‌خواهد

PasarGuard یک ردیف **Node** دارد. اگر آن را Enable کنید:

1. پنل از **آلمان** به API نود ایران وصل می‌شود: `https://<IP-ایران>:62050/start`
2. کل کانفیگ Xray + همهٔ کاربران را در body می‌فرستد
3. نود ایران پروسس `xray -c stdin:` را با آن JSON بالا می‌آورد

تا وقتی این مسیر سالم باشد، پنل خودش کاربر جدید را روی ایران اعمال می‌کند و آمار را می‌گیرد. اسکریپت `iran-sync-*` لازم نیست.

## چرا در این استک Enable نشد (و خطرناک است)

سه واقعیت با هم جمع شدند:

1. **هستهٔ زنده ایران docker است** (`pasarguard/node`). JSON روی دیسک `/root/.pg_nodes/iran/xray.json` را systemd اجرا نمی‌کند. تا `/start` نخورد، Reality روی `:443` کانفیگ پنل را ندارد.

2. **آلمان → ایران `:62050`:** نود جواب HTTP 200 می‌دهد ولی **body بزرگ است** (کل هسته + کاربران). کلاینت HTTP پنل روی خواندن body **timeout** می‌شود، retry می‌کند، و پنل وضعیت **LockControl** می‌گیرد. نود از نظر UI «خراب» می‌شود در حالی که Xray ممکن است نیمه‌کاره بالا آمده باشد.

3. **ایران → آلمان پنل روی IP خام / `:2096`:** DPI بعد از TLS، HTTP را می‌خورد. نود ایران نباید برای سینک به `panel:2096` عمومی poll کند.

نتیجهٔ عملی: Enable کردن نود در UI **مسیر رسمی را دوباره باز می‌کند** و همان timeout/LockControl برمی‌گردد. ردیف نود را **پاک نکنید** (تگ اینباند کاربران به همان نود وصل است) — فقط `disabled` / `keep_alive=0` بماند.

جایگزین که الان کار می‌کند:

- آلمان هر ۱۰ث از sqlite پنل protobuf می‌سازد → SCP به ایران
- ایران اگر hash عوض شده (یا `:443`/`:2053` خواب است) locally `POST https://127.0.0.1:62050/start`
- آمار را `iran-stats` با SSH و `xray api statsquery` به sqlite پنل می‌نویسد — چون نود disabled است پنل خودش usage را نمی‌پرسد

## روی سرور دوست می‌شود «درست» کرد؟

**شاید، بعد از اینکه استک با سینک SCP بالا آمد — نه در روز اول.**

تست اجباری از Exit جدید، قبل از هر Enable:

```bash
# از آلمان: آیا POST به نود ایران تمام body را بدون timeout برمی‌گرداند؟
# اگر curl به 62050 در کمتر از مثلاً 20s تمام شود و پنل timeout کوتاه‌تری دارد، باز هم ممکن است Fail شود.
curl -vk --max-time 60 -o /tmp/node-start.out -w 'http:%{http_code} time:%{time_total}\n' \
  --resolve node.example:62050:IRAN_IP \
  https://node.example:62050/health   # یا هر endpoint سلامت نود
```

اگر **هر دو** برقرار بود:

- آلمان می‌تواند TCP+TLS+HTTP کامل به `:62050` ایران بزند (فایروال فقط IP Exit)
- پنل PasarGuard شما timeout بالاتر از زمان واقعی `/start` دارد (باید با نسخهٔ پنل چک شود)

آن‌وقت **می‌توان** معماری رسمی را امتحان کرد: Enable نود، `iran-sync-export/apply` را متوقف کرد، و دید LockControl نمی‌آید.

اگر تست fail شد (احتمال زیاد وقتی یک سرور ایران و یکی خارج است): **همان طرح فعلی را نگه دارید.** این باگ محصول نیست؛ محدودیت شبکه + timeout کلاینت پنل است. «اصلاح» واقعی یا طولانی‌کردن timeout پنل است یا همین صف SCP.

**قانون پرامپت Cursor دوست:** تا وقتی تست `/start` از Exit موفق و تکرارپذیر نشده، نود را Enable نکن. ردیف را بساز و disabled بگذار.
